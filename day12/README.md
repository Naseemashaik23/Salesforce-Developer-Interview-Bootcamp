# Sprint 11 – Learning Outcomes

## What I Learned

### 1. APIs and REST
- Understood APIs as contracts between two systems.
- Learned REST and common HTTP methods.
- Learned how to read request and response structures.
- Understood JSON data exchange.

### 2. Salesforce API Integration
- Learned how Salesforce communicates with external systems using HTTP callouts.
- Understood why callouts are often handled asynchronously.
- Learned how Queueable Apex can be used for external API communication.

### 3. Authentication and Security
- Learned about Named Credentials.
- Understood the difference between authentication and authorisation.
- Learned the role of Auth Providers.
- Understood why secrets should not be hard-coded in Apex.

### 4. Integration Architecture
- Learned about Salesforce Connect and External Objects.
- Compared point-to-point integration and middleware.
- Learned when to choose synchronous or asynchronous integration.

### 5. Integration Reliability
- Learned how to handle API failures and unexpected responses.
- Understood retry strategies for temporary failures.
- Learned why idempotency is important for preventing duplicate processing.
- Learned how to track integration status such as Pending, Sent, Failed and Retry Required.

### 6. Practical Implementation
- Connected Triggers, Services, Queueable Apex and external APIs.
- Built an external recruitment integration for selected candidates.
- Created and documented an API contract.
- Tested different API responses and failure scenarios.

## Key Takeaway

I learned that Salesforce integration is not just about sending an HTTP request. It requires proper architecture, authentication, error handling, retries, duplicate prevention, status tracking and clear API contracts.
